# P2.10 — Intégration frontend ↔ backend : rapport

- **Statut** : **P2.10 clôturée et validée** (validation humaine de clôture accordée). Contre-épreuves CP-01 à CP-04
  réalisées et concluantes. ADR 0012 acceptée. Cette validation **ne vaut pas autorisation de déploiement en
  production** : voir §7 (limites) et §12 (clôture).
- **Décisions de cadrage** : D1 à D8 approuvées (périmètre, HTTP local et TLS activable, Vite en conteneur,
  QR code réseau-indépendant, trois modes d'API, `seed_demo` reporté à P2.11, modifications frontend justifiées,
  Nginx sur `127.0.0.1:8080` uniquement).
- **Commits** : livraison P2.10 et test complémentaire CP-03 (sans code de production) ; identifiants de commits internes retirés de cette version publique.
  Aucun push. Le commit P2.10 n'a pas été réécrit.

## 1. Périmètre livré

- Nginx comme point d'entrée unique (`127.0.0.1:8080`) : frontend sur `/`, API Django sur `/api/`.
- Adresse cliente centralisée (`apps.core.client_ip`) : proxy de confiance déclaré, en-têtes de transfert
  réécrits par Nginx et supprimés pour les autres pairs, réseau de proxy trop large refusé au démarrage.
- Frontend de développement en conteneur (Vite, rechargement à chaud par le proxy, `node_modules` en volume).
- Trois modes d'API côté frontend : tout simulé (P1), intégré (API réelle, MSW pour les seuls modules reportés
  avec la mention « Données simulées — module non encore implémenté »), production (MSW absent du bundle).
- Secrets d'authentification (TOTP, URI, codes de secours) : QR code dessiné localement, jamais dans l'URL,
  le stockage du navigateur, les journaux ou le cache des mutations ; codes de secours affichés une fois.
- TLS activable (`RBI_TLS=on`) : TLS 1.2 et 1.3, redirection HTTP vers HTTPS, HSTS sur HTTPS seulement, cookies
  `Secure`. Testé avec un certificat autosigné temporaire.
- Parcours E2E réels (`scripts/e2e.py`) dans un environnement jetable `rbi-e2e`.
- Documentation : ADR 0012, `backend/README.md`, `README.md`, feuille de route P2 mise à jour.

## 5. Contre-preuves

Méthode : sauvegarde du fichier, modification ciblée, exécution des tests, restauration vérifiée par SHA-256
(identique avant et après). Aucun `git checkout` ni `git restore`.

## 6. Défauts trouvés et corrigés pendant la phase

- **Violation CSP réelle** (parcours E2E) : les feuilles de style créées par la bibliothèque de fenêtres modales
  étaient bloquées (nonce absent). Corrigé en transmettant le nonce de la page à la bibliothèque
  (`src/main.tsx`) ; la politique CSP n'a pas été relâchée. L'ADR 0012 affirmait à tort « aucune violation » ;
  elle est corrigée.
- **Régression P1 corrigée côté test** : le test « lien d'évitement » partait d'un point de tabulation resté sur
  le bouton de connexion retiré par la redirection ; le test repart désormais d'un focus neutre. L'assertion
  ne change pas ; le lien d'évitement reste le premier élément focalisable.
- **Tests E2E** : sélecteurs ambigus (compte sans nom, où la colonne Nom reprend l'adresse) et une action d'audit
  mal choisie (`organization.activate` ne consigne que les refus ; une activation réussie est
  `organization.transition`). Corrigés sans affaiblir les assertions.
- **Lint backend** : 22 erreurs de longueur de ligne et d'import dans les nouveaux fichiers, corrigées ; un
  `try/except/pass` remplacé par `contextlib.suppress`.

## 7. Écarts et limites

1. **TLS** : testé uniquement avec un certificat autosigné généré pendant les tests. Non validé en production
   (certificat réel, chaîne, OCSP, préchargement HSTS).
2. **Un seul niveau de proxy** déclaré. Un répartiteur de charge en amont exigera de revoir la configuration.
3. **Build P1 par défaut** : `npm run build` sans variable produit le mode démo, qui embarque
   `mockServiceWorker.js` (comportement attendu hors production). Le build de production (`VITE_APP_ENV=production`)
   est celui qui exclut les mocks ; il est vérifié par test, pas par une image livrée.
4. **`qrcode.react`** : dernière version publiée en 12/2024 ; à réévaluer avant tout pilote réel (ADR 0012 §8).
5. **`seed_demo`** : non réalisé, reporté au début de P2.11 (décision D6). Les parcours E2E créent leurs données
   fictives eux-mêmes.
6. **Risques résiduels de la revue de sécurité interne** : restent ouverts et documentés. Le risque lié à l'adresse cliente est traité par l'ADR 0012.
7. Aucun test de charge ; aucun test d'intrusion indépendant.

## 12. Clôture et validation

- **Décision** : P2.10 clôturée et validée après validation humaine. ADR 0012 acceptée.
- **Portée de la validation** : elle clôt la phase d'intégration sur l'environnement local décrit ci-dessus. Elle ne
  vaut **pas autorisation de déploiement en production** : aucun certificat réel, aucun test d'intrusion
  indépendant, aucun test de charge, aucune validation de la configuration TLS hors environnement local.
- **Risques de la revue de sécurité interne** : aucun n'est clos par cette décision.
  Le risque d'adresse cliente est traité par l'ADR 0012, dans les limites de §7.
- **Commits de référence** : livraison P2.10, test complémentaire CP-03 (sans code de production), contre-épreuves (ADR 0012). Identifiants de commits internes retirés de cette version publique.
- **Restaurations** : chaque mutation des contre-épreuves a été annulée et vérifiée par SHA-256 (§5 bis). Une
  vérification ultérieure de l'état a confirmé que les fichiers du conteneur `proxy` et du dépôt correspondent à
  leurs versions validées, et qu'aucun marqueur de mutation n'est présent dans le code commité.
- **Résultats antérieurs et résultats nouveaux** : les chiffres de §4 et §5 bis sont ceux des exécutions déjà
  rapportées (backend 729 puis 730, E2E 9/9, Vitest 105, P1 32/4, audit 78 entrées, readiness 200). La clôture
  documentaire ne les a pas relancés. Vérifications faites à la clôture : branche et ordre des commits, arbre Git
  propre, empreintes des trois fichiers Nginx (conteneur et dépôt identiques), absence de marqueur de mutation dans
  le code commité, cohérence des statuts entre rapport, ADR et feuille de route.
- **Git** : branche `main`, arbre propre au moment de la clôture, aucun push.
- **P2.11** : non démarrée. `seed_demo` n'a pas été lancé et aucune donnée de démonstration n'a été créée. Démarrage
  soumis à une autorisation explicite.
